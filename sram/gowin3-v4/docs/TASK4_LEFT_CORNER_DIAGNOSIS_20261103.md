## 结论

**误判已定位到板端左出口识别，尚未定位到左侧测距与实际几何不符的唯一物理原因。**

板端将节点1发布为`EX=4`，只保留后方来路，没有左出口；上位机按这个掩码显示死路。实际应有的“后方来路＋左出口”为`EX=12`。

当前左侧开口条件相当于原始ToF读数至少435mm；本次采到约370～408mm，因此这些数值会被判为墙或结构未知。END23原直角版、END25黑色建图版和END26红色版的核心墙/开口判据相同；旧版与新版生产函数的直接数值诊断也得到完全一致的结果。

**没有发现“换红色视觉直接改掉直角判断”的证据。** 本次运行的视觉TOKEN/CONSUMED/REJECTED均0，未记录GOAL视觉确认阶段。对视觉后台可能产生的间接调度影响，尚未做同位置运行对照，不能仅凭源码相同就彻底排除。

## 2. 误判在哪一层

实际链路：

```text
左ToF原始读数
  → 减去60mm内缩量
  → 多帧确认后的导航缓存
  → wall/opening及exits()生成出口掩码
  → 板端发布节点EX
  → 上位机按出口数量标注节点类型
```

实际节点1记录：

```text
ID=1  PA=0  EN=2  EX=4  TR=0  G=0
```

内部方向：前0、右1、后2、左3。故`4=1<<2`只有后向来路；左拐应增加`1<<3=8`，合计12。

[上位机分类](F:/FPGA/apps/maze-navigation/pc_station/metric_map.py:53)按`exits.bit_count()==1`显示死路。也就是说，这次确实是板端漏报左出口，上位机没有自行把正确的左拐掩码改成死路。

## 3. 左出口为什么没有被认作开口

当前配置及生产函数：

- 通道宽600mm，车宽250mm，左探头相对车体边缘向内缩60mm。
- [raw_distance](F:/FPGA/build/soc/task4_red_presence/fw/maze_tof.c:65)：净距=原始读数−60。
- [wall/opening](F:/FPGA/build/soc/task4_red_presence/fw/maze_tof.c:30)：侧向中心净距=(600−250)/2=175mm。

因此：

```text
墙：净距 ≤ 175 + 600/4 = 325mm
    等价原始读数 ≤ 385mm

开口：净距 ≥ 175 + 600/3 = 375mm
      等价原始读数 ≥ 435mm

原始386～434mm：既不是已确认墙，也不是已确认开口
```

435mm是开口识别门槛，不是要求车与墙保持的最短距离。

本次左向实际查询均VALID1/ERR0/RANGE0，部分样本如下：

| 记录器时间 | 左X4原始读数 | 换算净距 | 代入现有判据 |
| --- | --- | --- | --- |
| 5.14s，启动前 | 217mm | 157mm | 墙 |
| 11.41s | 408mm | 348mm | 结构未知，未达到开口 |
| 18.17s | 401mm | 341mm | 结构未知 |
| 24.79s | 395mm | 335mm | 结构未知 |
| 31.72s | 391mm | 331mm | 结构未知 |
| 51.42s | 397mm | 337mm | 结构未知 |
| 58.04s | 370mm | 310mm | 墙 |
| 70.78s，停车后 | 371mm | 311mm | 墙 |

可见左侧读数确实从217mm增加到约400mm，但“增加了”并不等于当前代码会认作开口。[events()](F:/FPGA/build/soc/task4_red_presence/fw/maze_tof.c:207)还要求`opening()`成立，才能登记左侧开口事件。

必须区分：386～434mm的灰区会使`exits()`返回未知并等待几何条件，**不会直接把灰区登记为死路**。能够正式登记EX4，意味着登记当时左侧被接受的缓存按代码满足了墙判据，可能是较短的一帧或尚保留的旧墙缓存。登记瞬间的缓存没有冻结，不能把58.04秒的370mm当作当时的触发帧。

停止后只读取得左向核心缓存`D=3 / NET=332 / ACCEPT=1 / EPOCH=1`，也落在灰区。这是故障后保留的缓存，不是节点最初登记时的快照。该次查询的RAW是仍在更新的原始读数，两者并非同一帧；AAGE随故障锁停后的时间增长，不能用它反推故障瞬间失鲜。

## 5. 是否因为更换红色视觉

本轮没有记录到GOAL状态，视觉请求/消费/拒收计数全0，且红色版与黑色建图版的转角逻辑逐字相同。因此不支持“红色确认分支直接把左拐改成死路”的判断。

当前已经有足够证据解释近因：**左侧被接受的距离未形成左出口，EX少了左向位，节点被登记为只有来路。**

仍待定位的是为什么实际左直角对应的测量/缓存只在约370～408mm附近：可能涉及停靠位置、探头视线/遮挡、转角实际几何与既定600mm模型的关系，或缓存确认过程。没有登记时完整数据和现场测距对照，尚不能唯一选定其中一项。视觉服务工作负载的间接时序影响也未做同位置对照，暂不作彻底排除。

后续应优先核对左X4实际照到的墙面/边缘，以及开口开始到节点登记期间的左原始帧、accepted缓存和pending过程，再决定调整哪里。本轮没有改视觉、门槛、定时或限幅，也没有再发车。
