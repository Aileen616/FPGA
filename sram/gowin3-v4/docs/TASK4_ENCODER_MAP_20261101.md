### 接口与调用流程

- `mo_defaults(c)`、`mo_init(o,c)`、`mo_update(o,in)`：初始化并消费新四轮快照。计数按FL/FR/RL/RR归一。默认复用原项目5268.945counts/m，不宣称为新的实车标定结果。不同轮子可分别配置换算系数。
- `mt_defaults`、`mt_init`、`mt_start`、`mt_tick`、`mt_cancel`：保留原导航接口，新增输入`encoder`及配置功能选择`mapping_enabled`。
- `mt_request_target(n,id)`：对已经完成的地图准备一个已知节点任务；仍由原运动入口启动，不提供新的许可解锁。
- `mt_map_event(n,after,id,next)`：读取节点变更；返回0无变更、1有记录、2需要全图同步。

板端在原10ms运动调度中锁存同组四轮计数，沿用`canonical_bit`和原物理位反向掩码5。只写快照位，不清计数、不改输出模式、不续驱动租约。编码器有效性仅影响地图里程标记，不成为新的停车或启动条件。地图不依赖电脑按时轮询才能累计。

任务开始时在软件中建立起点原点，不清硬件编码器。x向初始右方、y向初始前方，单位毫米；内部保存微米和定点换算余数。IMU航向右转为正。横移、前后和航向纠偏经过四轮运动学分解，不使用计数绝对值总和或PWM×时间冒充位移。

节点以原ToF对齐/停车确认位置登记。首次记录位置和父边长度，复访按已知父子关系复用编号，并记录里程复访误差；不按坐标接近合并节点，不把计程误差反向注入ToF控制。

```text
探索建图
  ├─确认终点 → 登记终点节点 → 继续其他支路
  └─支路完成 → 返回父节点
全部支路完成 → 返回已知终点 → 到点待命
明确选择目标节点 → 原ToF逐段行走 → 到点待命
```

起点本身也入图并可作为目标。返回起点使用起点保存的原ToF参考距离，沿用原有运动间隙判断。已知节点路线保留实际来向，避免把每次节点任务的来向错误重设为前向。确认过的终点观察不在每次复访时重复请求。

## 没有新增的运动限制

- 原`maze_drive.inc`逐字一致，原混合器、Q15范围和试跑路径保持。
- 原ToF的`guard`、`move`、`approach`、`settled`、`observe_range`、`observe_imu`函数逐字一致。
- 没有新增车辆总运行时限、试跑输出比例上限、强制分段试跑或编码器标定许可。
- 原生产入口已有120秒分支保留；原试跑路径仍不套用该总时限，新增已知节点任务沿用此前任务的试跑/生产模式。不能把“未新增”写成所有既有入口都没有时间处理。
- 地图消息队列满时丢弃本条遥测，由电脑重试，不触发新的停车或限幅。16条增量历史是通信缓存；溢出后全图补传，不停止探索。
- 沿用原32节点静态容量，没有另加更小的任务配额。数字表示范围检查只标记里程无效，不限制车辆运动。
- 上位机“验证通信（8组）”只用于旧的诊断采集。新“接收节点地图”持续接收；8组不限制车辆或建图任务。

## 通信与上位机

仍使用电脑SSH到香橙派、香橙派UART到FPGA。地图中转源码由SSH送入内存，不需要安装常驻服务。新模式允许活动期间读取地图；不使用行驶时会返回BUSY的旧`enc live`接口计程。

| 指令 | 回复 | 用途 |
|---|---|---|
| `map pose` | `MP` | 会话、版本、节点数、最后确认节点、阶段、终点、当前里程 |
| `map node <id>` | `MN` | 编号、父节点、出口、探索状态、毫米坐标、父边长度、复访误差 |
| `map event <revision>` | `ME` | 增量节点通知，历史不足时请求全图同步 |
| `map goto <id>` | `MG OK=0/1` | 明确下发一个目标，回复仅表示是否接受，不能当作已到达 |

上位机按节点编号及父子关系连线；毫米坐标允许计程漂移，不再套用电脑草图的整数网格及严格共线规则。记录带会话和版本，重连拉取当前地图，旧节点版本不覆盖新记录。未知父节点可等后续补齐；错误环路拒绝显示。

地图显示中的小方块是里程估计位置，外圈是最后确认的节点，两者在行驶中可以不同。离线回放、历史地图与在线地图明确标注。只有地图模式下明确点击“前往选中节点”，才发送目标请求；回放与电脑演示不会发车。

本轮没有启动SSH或打开串口，新通信代码只用假串口与真实C生成的协议记录测试。新协议的实际刷新速度未测量；原先约3秒的旧诊断整组时间不能作为它的延迟。

## 内存配置与构建

首次完整目标链接超出原64KiB指令区，错误保留在本轮过程输出；没有裁剪原控制、视觉或显示功能。依据本地官方`references/softcore/IPUG911.txt`的存储映射和`IPUG914.txt`的ITCM选项，仅独立候选把ITCM改为128KiB，DTCM仍64KiB；原CPU加密IP和电机RTL不修改。链接布局、ROM长度和公开CPU参考模型一起更新。

最终固件70472字节；实际摘要、BSS与栈检查数据见`build/soc/task4_encoder_map/review.json`和`firmware/command_25.log`。保留原4KiB栈空间链接断言；单函数静态栈报告不等于实物最坏栈高水位证明。

Gowin仅运行综合，没有运行布局布线或生成FS。综合使用128KiB配置，资源报告在`gowin_synth/competition_mono/impl/gwsynthesis/`。已有时钟关系警告保留，不作为板级时序通过。

## 仿真与静态验证

最终结论以`review.json`的输入摘要核对为准，不沿用中间ROM的通过记录。

1. `test_task4_encoder_map.py`：O0/O2共16组真实C几何闭环，包含完整探索、计时回绕、编码器比例偏差12%、人工停止、旧模式、全部节点对、无终点、测距噪声；另有里程方向、计数/序号回绕、分数余数和重复快照测试。
2. 完整探索模型在57秒左右发现终点时仅6节点，继续补齐到8节点后返回终点，随后能执行节点导航。8节点全部64种起终点组合分别在O0/O2测试；通过中间重新定位请求生成128次目标请求，模型累计约4270秒，未加入车辆运行总时限。
3. 将编码器换算比例改动12%，行走时序、节点数、路线和到点事件与正常里程模型一致，仅地图尺寸变化，证明编码器旁路不控制原ToF运动。
4. `test_task4_encoder_map_legacy.py`：新增核心关闭建图功能时，原50组几何及异常用例回归。
5. `test_task4_encoder_map_controls.py`：原控制、蓝牙/PS2、视觉隔离及新增板端接入，O0/O2各119955项检查；同组快照、实际位反向归一、起点原点、协议不改输出、队列满不停车、旧试跑超300秒不被额外总计时停机均覆盖。
6. `test_task4_encoder_map_cpu.py`：最终实际RV32机器码、公开PicoRV32指令参考及真实外设RTL，两次启动及25项协议/默认停止检查。公开参考不等价于加密Gowin CPU的逐周期模型。
7. 上位机单元测试覆盖旧诊断、C生成协议、完整几何记录回放、版本/会话、增量/补传及明确目标请求；Tk窗口检查回放2358条真实C记录并选点，截图在`host/ui/metric_map_preview.png`。均未建立真实连接。
8. 目标RV32构建、Gowin综合和最终源/固件/仿真摘要核对。

## 验收边界

本轮硬件访问、SRAM、Flash、标定、车辆启动均0，不声称实机完整迷宫通过，没有生成可下载FS。

- 编码器正常由用户确认；本轮未重新实测轮序、计数每米、横移滑移、地图尺寸误差或动态服务时序。
- 终点仿真使用明确的新token、独立图像序号和充分视野输入。板端补通完整新鲜阳性的接收路径，但阴性仍需原有视野覆盖依据；未把整幅暗图或零候选直接当作可靠阴性。实际终点画面、安装覆盖与暗图问题仍待实物验证，不能据模型结果宣称已解决。
- 原ToF不可达对齐目标（如旧TARGET17/46）及参考/测距故障场景没有通过本轮改地图自动消失；原运动函数按用户要求保留。当前通过的是列出的独立墙线段模型，不覆盖所有真实摆位和速度。
- 128KiB配置综合通过不代表布局布线、时序、上板或完整SRAM读回通过。
- 新上位机到板端协议只有离线接入证据，没有新的有线/无线实机通信结论。
