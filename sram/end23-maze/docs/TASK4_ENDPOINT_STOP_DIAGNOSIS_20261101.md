# 迷宫在黑色终点挡板处停止的排查

用户现场补充：最近几次停车实际都发生在终点黑色挡板位置。此前只按导航故障码报告“异常停车”，没有结合现场位置检查终点链路，结论不完整。物理到达终点、程序判定终点成功、故障导致输出归零是三件不同的事，本次只能确认前者为用户观察，后两者需要各自证据。

本次沿用 SRAM 中 END23／ALG4／MZ13／FIX2，完整 FS SHA256 为 `535394d3c9d3de5abc64faa5f8df71383207914951cee2b35870bd255e8e2db5`。未改导航、识别源码或参数，SRAM 写入、Flash 写入、发车均为零。为回收一张同帧原始图，临时暂停了自动识别，导出后恢复 RUN=1，并读到新的发布序号；四轮 PWM/TARGET/ACTIVE 均为零。

## 一、行驶记录没有建立终点确认请求

最近两次完整记录 retest_004、retest_005 的终态都是 `TOKEN=0 CAPTOKEN=0 CONSUMED=0 REJECTED=0 FRAMES=0`。导航采样没有观察到 MT_GOAL；更直接的证据是请求 token 从未递增，因此不能把这些记录描述成“已经请求识别，视觉返回阴性”。早先 run_001、retest_002 保存的 IO 也都是零 token，但记录在手动结束前停止，终止操作证据另存。retest_003 完整日志尚缺，不补造同样结论。

`maze_tof.c` 的 MT_DECIDE 只有在出口位图严格等于“只剩来路”时才发起视觉请求。只要左右还测到通路，前面即使是终点挡板，也会继续按路口选择处理。retest_005 后段记录前距约 152 mm、右距约 2475 mm、左距约 224 mm，导航方向后来成为右向。这与“前面有挡板就应停车观察终点”的任务意图不一致。

此外，通用 guard 在 MT_GOAL 分支之前执行。因此即使将来进入停车识别，只要运动所需侧向参考等条件失效，仍可能先被锁成故障，不能用“相机一定漏检”解释全部停车。

源码依据：冻结 `build/soc/task4_maze_corner_fix/fw/maze_tof.c` 中 guard、MT_DECIDE 和 vision_tick；记录依据 `hardware/retest_004/motion_004/result.json`、`hardware/retest_005/motion_005/result.json`。

## 二、运动路径的视觉接收开关仍然关闭

冻结 `maze_drive.inc` 中 `maze_drive_config` 是静态零初始化变量，当前源码没有为 `coverage_verified` 赋值的路径。运动服务调用：

```c
maze_vision_feed(now, maze_drive_config.coverage_verified && maze_shadow.dir == MT_FRONT);
```

因此，即使导航已经进入 MT_GOAL，当前版本也不会消费识别结果。试跑只绕过了运动动态系数的准入，并没有打通这个视觉接收条件。

过去 `maze goal 1` 静态检查使用单独的 `maze_coverage`，与上面的运动接收开关不同。此前静态 token／多帧确认通过，不能推出自动行驶中的终点接收已经可用。这个接入缺口需要修正，而不是通过扩大超时或修改故障名称解决。

## 三、当前确实存在零候选画面，但不是没有采集

本轮被动查询观察到发布序号 68→69→70，ERROR=0。SEQ69、70 的新鲜结果均为零候选。随后冻结 SEQ90，板端同样 COUNT=0，并导出完全一致的 100×60 RGB565 图像。

图像 SHA256 为 `5704f59e05cfba105c74a8c539d20797bfdc2500d52473af64b925022c158106`。使用当前生产 `endpoint_black.c` 分别以 O0、O2 编译回放，再与 ALG4 Python 参考核对，四方均为零候选、无算法错误。

回收画面几乎全暗：95.53% 像素的最大 RGB 通道值低于 64。阈值 48、64、80 下的最大暗连通域都覆盖到 100×60 图像边界。当前检测器要求有完整且不触边的方形区域，所以这些大暗区会被拒绝。

当前前 ToF 约 151 mm。可能是黑板距离过近占满视野，也可能涉及镜头朝向、遮挡、曝光或现场背景；仅凭这张暗图还不能认定具体原因。尚未人工确认图中哪个区域就是物理标记。不能直接把“整幅图很黑”改判为终点，否则遮挡镜头和暗环境也可能产生相同结果。

图像：`build/soc/task4_maze_corner_fix/hardware/endpoint_diagnosis_20261101/frozen/preview.png`。

## 四、下一次修复应覆盖的完整链路

1. 在初始前向接近挡板并停车时建立终点观察候选，不再必须先被判定为只有一个出口的死路；是否为终点仍由视觉确认，普通墙面不能直接判成功。
2. 将停车视觉观察条件与运动动态标定许可分开，使试跑能够按真实观察条件接收新 token 的图像。保留采集时间、序号、多帧和目标完整性核对。
3. 将“停止运动”与“取消终点观察”分开处理。运动参考不足时继续停机，不能再移动；但不应无条件阻止仍可进行的静态视觉诊断。真实传感器故障不得被伪装成终点成功。
4. 根据终点标记尺寸、安装高度、镜头视野确定可看到完整轮廓的观察位置。先在当前终点摆位取得可识别画面，再验证车辆是否能进入同一观察条件。
5. 成功结束必须同时看到终点请求、新鲜正结果被消费、导航 MT_DONE、四轮零输出；到达黑板附近或某个 WHY 故障停车都不能替代这些证据。

本轮仅诊断，尚未实施上述修复。没有新增运行时限或输出限制。
